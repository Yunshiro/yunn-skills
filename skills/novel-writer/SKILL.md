# 小说创作工坊

将用户输入的主题、类型与大纲，自动生成完整的小说，包含角色DNA档案、故事大纲、情绪节拍表、分章节创作与分层润色。

**双模式**：

- **商业网文模式**（七猫/番茄/起点等平台投稿）——黄金三章、爽点节拍、强制反 AI 味规则
- **文学模式**（纯文学/征文/自留）——麦基剧作法、留白美学

★ 阶段一必须先确认平台/赛道来判定模式，两套规则不可混用。

★★ **商业网文模式下，两条规则优先级最高，顺序不可颠倒**：

1. **代入感**（5.3-L / 6.0）——读者要能钻进主角身体里。**这是免费平台编辑退稿率最高的一项**
2. **去 AI 味**（5.3-A~K / 6.1）——不能有模具感

两者冲突时**一律以代入感为准**。把去 AI 味的"删心理活动、删描写、句句推进剧情"执行到极致，会把稿子写成外视角摄像机：技术上零瑕疵，编辑评语是"节奏很快，但代入感不足"。

## 触发条件

用户明确提出"写小说""创作故事""生成小说"等请求，或直接调用此 skill。

## 输出目录规则

所有生成的文件**必须**保存到当前项目目录下的 `output` 文件夹中，按类型分目录存放：

```
项目目录/
  output/
    ├── 章节正文/                  ← 所有章节正文
    │   ├── 第1章·[章节标题].md
    │   ├── 第2章·[章节标题].md
    │   └── ...
    └── 创作材料/                  ← 角色DNA、节拍表等规划文档
        ├── [标题]-角色DNA档案.md
        ├── [标题]-情绪节拍表.md
        └── （可选）润色笔记等
```

若 `output` 或其子目录不存在，先用 `mkdir -p` 创建。文件路径规范：`./output/章节正文/第N章·[章节标题].md`、`./output/创作材料/[标题]-角色DNA档案.md` 等。

## 运行模式

本 skill 分为 **五个阶段**，按顺序执行。每完成一个阶段，向用户展示成果并请用户确认或提出修改，确认后再进入下一阶段。

### 篇幅模式

Skill 根据章节数自动切换运行模式：

| 模式           | 章节数 | 总字数   | 节拍表粒度                    | 创作节奏                   |
| -------------- | ------ | -------- | ----------------------------- | -------------------------- |
| **中短篇模式** | ≤12章  | ≤50000字 | 逐章细化                      | 每章确认后动笔             |
| **长篇模式**   | ≥13章  | ≥50000字 | 按"卷/弧"分组，每组内逐章细化 | 按卷批量生成，卷内连续输出 |

长篇模式下，阶段三的节拍表先按"卷（3-5章为一卷）"定大弧线，再在阶段四对当前卷内的每一章展开逐章参数。用户只需在每卷开始前确认一次，卷内各章连续生成无需逐章确认。

## 阶段一：需求采集

向用户收集以下信息（用户已提供的则跳过）：

1. **发表平台/赛道**（**必问，决定后续所有规则**）：
   - **免费阅读平台**（七猫 / 番茄 / 得间 / 疯读）→ 自动启用 **商业网文模式**
   - **付费订阅平台**（起点 / 掌阅 / QQ阅读）→ 启用商业网文模式，节奏可略缓
   - **纯文学 / 自留 / 征文**（豆瓣、公众号、文学奖）→ 启用 **文学模式**
   - 用户未指明时默认询问；说不清楚则按**商业网文模式**处理
2. **小说类型**：都市异能 / 玄幻修真 / 系统流 / 悬疑 / 言情 / 科幻 / 现实主义 / 历史 / 其他
3. **故事主题/内核**（一句话概括核心冲突与主线）
4. **金手指设定**（商业网文模式必问）：主角凭什么翻盘？一句话说清机制和代价
5. **篇幅规划**：总字数（默认20000字）、章节数（默认8章）、每章字数（默认2500字）
   - 若章节数≥13或总字数≥50000，自动切换为**长篇模式**
6. **主要人物数量**（2-4个，默认4个）
7. **故事时代/地域背景**（如"当代中国小镇""近未来都市""架空王朝"）
8. **特殊要求**：叙事视角（第一人称/第三人称限知/全知）、是否有参考作品（对标书名最有用）等

### 两种模式的规则差异（贯穿全流程）

| 维度     | 商业网文模式                       | 文学模式                  |
| -------- | ---------------------------------- | ------------------------- |
| 结构方法 | 黄金三章 + 爽点节拍（阶段三 A 套） | 麦基剧作法（阶段三 B 套） |
| 情绪曲线 | 锯齿上行，首章强度≥7               | 单峰上扬，首章强度 4-5    |
| 章末     | 必留悬念，禁止留白式收尾           | 可留白                    |
| 点题     | 允许说透，情绪要给足               | 忌直白点题                |
| 爽点密度 | 每 2000 字≥1 个爽点落地            | 不作要求                  |
| ★叙述视角 | ★贴身限知，每 500 字≥2 处主角感知句 | 可用全知、可切视角        |
| ★主角内心 | ★必写，每个剧情节点挂情绪          | 可克制、可留白            |

**叙事风格不再让用户在"克制留白/细腻抒情"中选择**——商业网文模式下"克制留白"是负面项，会直接导致编辑评价"节奏慢、冲突不够"。

收集完毕后，输出一份 **《故事规划确认表》**，包含以上所有条目 + 判定出的模式，请用户确认。确认后进入阶段二。

## 阶段二：角色DNA档案生成

根据第一阶段确认的信息和小说类型，为每个主要角色生成完整的 **《角色DNA档案》**。

**生成原则（适用于所有类型）：**

- 每个角色的深层背景（童年经历/核心恐惧/内心渴望）必须能推导出ta的行为特征，不能矛盾
- 核心恐惧必须和故事主线产生关联——角色的恐惧就是ta在故事中被反复考验的东西
- 行为特征要具体到"一个外人能观察到的标志性动作/语言习惯"，不能写成抽象性格描述
- 人物关系张力提示要具体到"冲突类型"和"情感燃料"，不写泛泛的"关系复杂"

**标志性动作的使用纪律（防止机械复用，这是 AI 味的重灾区）：**

- 每个标志性动作在 DNA 档案里必须同时写出 **3 种变体**（放松时 / 紧绷时 / 失控时），正文中按情境选用，**严禁逐字复制同一句描述**
- 同一个动作在**同一章内最多出现 1 次**；相邻两章最多出现 1 次
- 动作必须**贯穿全书**，不能前几章密集使用、后面彻底消失——在档案里标注"预期出场章段"
- 动作要有**演化**：随着角色成长，同一个动作的含义或形态应发生变化（如"掐关节"从压抑愤怒→变成计算前的习惯→最后彻底消失），这个演化在档案里写明

**商业网文模式补充：**

- 每个反派必须有**明确的轻蔑台词模板**（他看不起主角时会怎么说），爽点场景要用
- 每个主要配角必须标注**"反馈功能"**：他是负责震惊的、负责传播的、负责嫉妒的、还是负责认可的。网文的爽感靠配角反应放大，没有反馈功能的配角是废角色
- ★★**必须指定 1-2 名"情绪代理人"**（见 5.3-L6）：性格外放、藏不住话，专门在爽点现场替读者把情绪喊出来。给他写好**炸开时的语言习惯**（叫法、口头禅、动作），爽点现场只用他，★禁止用"有人""众人"顶替
- ★★**主角必须写一份"感知清单"**（代入感的基础素材，见 5.3-L1/L5）：
  - 他紧张时身体哪里先有反应（后脖颈、手心、胃里、嗓子眼——★固定 2-3 处，全书复用同一套）
  - 他饿/疼/怕的时候具体是什么感觉（写成 3-4 句可直接调用的句子）
  - 他做判断时脑子里的语气（急、稳、毒、自嘲——决定全书内心独白的腔调）

**模板：**

```markdown
# 《[标题]》—— 角色DNA档案

> 故事内核：[一句话概括]

---

## 主角：[姓名]（[年龄]岁，[职业]/[身份]）

**基本信息**
- 姓名：
- 年龄：
- 职业/身份：

**深层背景**
- 童年经历：（1-2个具体事件/场景，解释角色为何形成当前性格）
- 核心恐惧：（ta最怕发生什么，这件事如何驱动ta在故事中的行为）
- 内心渴望：（ta真正想要的是什么，不一定是ta嘴上说的）

**行为特征**
- 说话习惯：（一个独特的口头禅或语言节奏，紧张/专注时的变化模式）
- 身体语言：（1-2个标志性小动作，在不同情绪状态下的表现）
- 思维模式：（ta处理信息的方式，判断人/事的底层逻辑）

---

## 配角：[姓名]（[年龄]岁，[职业]）

[同上结构，每个配角独立一段]

---

## 人物关系张力提示

- **[角色A] vs [角色B]**：[冲突类型] + [关系本质]
- **[角色A] vs [角色C]**：[冲突类型] + [情感燃料来源]
```

保存到 `./output/创作材料/[标题]-角色DNA档案.md`（目录不存在则先创建）。

## 阶段三：故事大纲生成

根据第一阶段确认的故事内核、类型和角色DNA，生成 **《故事大纲》**。

**按阶段一判定的模式，走对应的一套：**

- **商业网文模式** → 走 **3A（黄金三章 + 爽点节拍）**，跳过 3B
- **文学模式** → 走 **3B（麦基剧作法）**，跳过 3A

> ⚠️ 严禁在商业网文模式下使用麦基剧作法。麦基的"激励事件在前 1/4 处"对 250 章长篇意味着金手指可以拖到第 60 章——这在免费阅读平台等于直接扑街。两套方法论不可混用。

## 3A 商业网文大纲（免费/付费阅读平台）

### 3A.1 黄金三章铁律（不可妥协）

免费阅读平台的读者弃书判定发生在**前 300 到 500 字**。以下节点必须落到位：

| 位置                    | 必须发生的事                                                 |
| ----------------------- | ------------------------------------------------------------ |
| **第1章 开篇 300 字内** | 主角处境的**具体困境**用一个动态场景砸出来，不铺环境、不写回忆、不抒情 |
| **第1章 500 字内**      | ★**金手指/异变/核心悬念落地**——读者必须在这里知道"这本书的爽点机制是什么" |
| **第1章 章末**          | 主角**已经用金手指做成了一件事**，哪怕很小。不能只是"获得了力量"就结束 |
| **第2章**               | ★**第一次当面打脸**。轻蔑者在场、有台词、有围观者、主角有回应 |
| **第3章**               | 抛出**第一个中期目标**（大目标的第一级台阶）+ 亮出**第一个强敌**，让读者知道后面在追什么 |

**开篇 300 字的禁区**（违反即重写）：

- ✗ 天气/环境/建筑描写开篇
- ✗ 主角回忆童年或过往
- ✗ 连续两段以上的心理活动
- ✗ 世界观/设定解释

**开篇 300 字的正确做法**：从一个**正在发生的冲突场景**切入——有人在羞辱他、有个通知在逼他、有件事马上要发生。惨状是通过这个场景**顺带交代**的，不是单独铺陈的。

★★**开篇 300 字的代入感铁律（与上面的禁区同等重要，见 5.3-L）**：

- ★冲突场景必须**从主角的感知里写**，不是从摄像机里写。读者第一句就要"站在主角的位置上"往外看
- ★开篇 300 字内至少 **2 处主角感知句**（他听见 / 他觉得 / 后背发凉 / 心里那句话）
- ★开篇 800 字内至少 **1 处身体感官**（饿、疼、冷、渴），让读者的身体先和主角同步
- ★**人名 ≤3 个、地名 ≤1 个**（500 字内计），不出现要读者算术的数据，不解释任何计量单位
- ★**主角在拿到金手指之前必须是个普通人**：会怕、会疼、会屈辱。开局就满级冷静，读者贴不上去

### 3A.2 爽点节拍设计

**密度要求：每 2000 字至少 1 个爽点落地。**

**每个爽点必须四要素齐全，缺一不可：**

1. **铺垫轻蔑**——对手/围观者明确表达看不起，**必须有台词**，不能只写"眼神轻蔑"
2. **反差展示**——主角做到对方认定不可能的事，过程要短、要脆、要有画面
3. **当面反馈**——★**最容易被写漏的一环**。必须写出：对手的失态（具体动作/表情）+ 围观者的议论（**要有台词**）。严禁用"全场安静""没有人说话"来代替反馈，那是文学写法，读者拿不到爽感
4. **主角回应**——一句短台词或一个明确姿态。★**严禁主角全程沉默、冷处理、转身就走**

> 冷处理（已读不回、不作解释、留白转身）是文青审美。网文读者要的是**当场收账**。主角可以酷，但必须给出可感知的回应。

**爽点类型库（相邻爽点不得同类型，强制轮换）：**

| 类型          | 说明                             |
| ------------- | -------------------------------- |
| 实力打脸      | 当场展示碾压性实力               |
| 身份揭露      | 被看不起的身份反转成对方惹不起的 |
| 打赌/立誓兑现 | 对方立下狂言，主角当场兑现       |
| 抢夺/截胡     | 从对手手里拿走他志在必得的东西   |
| 反向索赔      | 对方施害后被加倍讨回             |
| 权威认可      | 大人物当众为主角背书，打脸小人物 |
| 情报碾压      | 用信息差让对手措手不及           |
| 救场          | 在对手失败处轻松解决             |

### 3A.3 冲突升级表（防止"原地踏步"）

大纲中必须列出这张表，**每卷一行**：

```markdown
| 卷 | 对手 | 对手层级 | 冲突类型 | 主角这一卷失去了什么 | 卷末爽点 |
|----|------|---------|---------|-------------------|---------|
| 一 | ... | ... | 个人恩怨 | ... | ... |
| 二 | ... | 高一级 | 势力打压 | ... | ... |
```

**硬性要求：**

- 每卷对手实力**必须高于上一卷**，不允许同级重复
- 冲突类型**必须更换**，推荐升级路径：个人恩怨 → 势力打压 → 资源争夺 → 立场对立 → 理念之争
- **同一个反派不得连续三卷担任主要对抗力量**——他要么被解决，要么退居幕后换人上
- 每卷主角**必须付出代价**（失去某样东西、欠下某个人情、暴露某个秘密），只赢不输的主角读者会腻

### 3A.5 商业网文大纲自检清单

```
□ 第1章 500 字内金手指是否落地？
□ 第1章 开篇 300 字是否零环境描写、零回忆、零设定解释？
□ 第1章 章末主角是否已经用金手指做成了一件事？
□ 第2章是否有当面打脸，且四要素（轻蔑台词/反差/当面反馈/主角回应）齐全？
□ 第3章是否抛出了中期目标和强敌？
□ 爽点密度是否达到每 2000 字 1 个？
□ 相邻爽点是否属于不同类型？
□ 每卷对手是否比上卷强？冲突类型是否更换？
□ 是否有反派连续担任三卷以上主要对抗力量？（有则拆分）
□ 每卷主角是否付出了代价？
□ 每卷末是否有大爆爽点 + 明确钩子？
□ 是否存在"主角全程冷处理、不回应"的场景？（有则改写）
□ ★第1章开篇 500 字内人名≤3、地名≤1，且无需要读者算术的数据？
□ ★第1章金手指首现是否规划了"懵→试→爽"三拍？
□ ★第1章前 1/3 主角是否先展示了普通人的弱（怕/疼/屈辱/无力）？
□ ★是否已在角色 DNA 里指定了 1-2 名"情绪代理人"？
□ ★每个大爽点是否都不需要读者做算术就能接收到？
```

自检不通过的项目，回到大纲修改，直到全部通过。保存到 `./output/创作材料/[标题]-故事大纲.md`。

## 3B 文学模式大纲（麦基剧作法）

> 仅在阶段一判定为**文学模式**时使用。

### 3B.1 大纲生成原则

**结构层级检查（节拍→场景→序列→幕→故事）：**

大纲中的每一个场景必须通过以下测试：

- **价值转折**：场景开头和结尾，人物的核心价值（如希望/绝望、自由/奴役、信任/背叛）必须发生变化。没有价值转折的场景是"废戏"，直接删掉或合并。
- **幕高潮**：每一幕以一个重大转折为顶点，导致人物处境发生不可逆转的改变。

**故事三角定位：**

生成大纲前，先根据故事类型确定结构路径：

| 类型                   | 特征                                       | 适用                                   |
| ---------------------- | ------------------------------------------ | -------------------------------------- |
| **大情节（经典设计）** | 主动主人公、因果驱动、线性时间、闭合式结局 | 悬疑、科幻、奇幻、历史、大多数商业小说 |
| **小情节**             | 弱化外部冲突，侧重内心挣扎，常开放式结局   | 现实主义、青春校园、文艺小说           |
| **反情节**             | 打破因果、非线性、荒诞解构                 | 实验性作品（新手慎用）                 |

默认采用大情节。若用户的故事类型更适合小情节（如现实主义/文艺），则自动匹配。

**必须锁死的核心节点：**

大纲中以下节点不可模糊，必须在明面上标注：

1. **激励事件（Inciting Incident）**：必须在前1/4处出现，是一个**动态事件**（不是内心感想）彻底打破主角生活的平衡，逼他行动。不能藏在背景里。
2. **故事脊椎（Story Spine）**：主角为了追求欲望而贯穿全书的线索。大纲中所有次情节不能抢主线的风头。
3. **进展纠葛（Progressive Complications）**：从激励事件到高潮，冲突逐级升级。阻碍不能原地踏步——风险、代价越来越大，人物每次行动都预期落空（**鸿沟原理**：现实反应违背主角预期）。
4. **危机（Crisis）**：高潮前的两难选择，不可回避。
5. **高潮（Climax）**：全书最大价值的转折点，主角与对抗力量的最终决战，必须不可逆转地改变人物命运。
6. **结局（Resolution）**：新平衡建立，所有核心问题闭合。

### 3B.2 步骤大纲（Step Outline）模板

用简洁的**单句或复句**描述每一个场景：发生了什么、转折在哪、属于哪一阶段。先不写对白和细描，只搭因果链，确认每个场景都有存在理由。

```markdown
# 《[标题]》—— 故事大纲

类型定位：[大情节 / 小情节]，[一句话说明理由]
故事脊椎：[主角]为了[欲望目标]，必须[行动主线]，但[对抗力量]不断阻挠。

---

## 第一幕：建置（Setup）

**场景1**：[一句话描述场景内容] → 价值转折：[从X到Y] → 所属节点：[激励事件前奏]
**场景2**：[一句话描述] → 价值转折：[从X到Y] → 所属节点：[铺垫]
**场景3**：[一句话描述] → 价值转折：[从X到Y] → 所属节点：★**激励事件**（第[N]章）

---

## 第二幕：进展纠葛（Progressive Complications）

**场景4**：[一句话描述] → 价值转折：[从X到Y] → 鸿沟：[主角预期X → 实际发生Y]
**场景5**：...
**场景6**：... → 所属节点：**幕中高潮/转折**
...

---

## 第三幕：危机与高潮（Crisis & Climax）

**场景X**：[一句话描述] → 价值转折：[从X到Y] → 所属节点：★**危机**（两难选择）
**场景X+1**：... → 所属节点：★**高潮**（不可逆转的价值转折）

---

## 结局：新平衡（Resolution）

**场景X+2**：[一句话描述] → 价值转折：[从X到Y] → 闭合：[什么被解决了，什么被永久改变了]
```

### 3B.3 大纲自检清单

生成大纲后，逐项检查：

```
□ 激励事件是否在前1/4处出现？是否是一个动态事件（而非内心感想）？
□ 故事脊椎是否清晰？从头到尾是否有一个主线不被次情节淹没？
□ 每个场景是否有价值转折？有没有"废戏"需要删减或合并？
□ 冲突是否逐级升级（鸿沟原理）？风险/代价是否越来越大？
□ 高潮是否不可逆转地改变了主角的命运？
□ 结局是否建立了新平衡？所有核心问题是否闭合？
□ 因果链是否成立？有没有"因为编剧需要所以发生"的强行推进？
```

自检不通过的项目，回到大纲中修改，直到全部通过。

保存到 `./output/创作材料/[标题]-故事大纲.md`。

## 阶段四：情绪节拍表生成

根据故事大纲、类型、章节数和角色关系，生成 **《章节情绪节拍表》**。

**通用原则：**

- 情绪强度用1-10级标注
- 核心事件必须可直接转化为该章的创作指令
- 每章转折点放在章节最后15%篇幅内

### 4.1 情绪曲线（分模式）

**商业网文模式——锯齿上行型（默认）：**

```
第1章必须 ≥7 起步。全书走势示例：
7 → 6 → 8 → 7 → 9 → 8 → 10 → 9 ...
     ↑小回落     ↑小回落      ↑小回落
```

硬性规则：

- ★**第1章强度 ≥7**，且章内必须完成 `低 → 高` 的完整跃迁（开篇困境 → 章末已用金手指做成一件事）
- **每一章内部都必须有独立的小高潮**，不允许有"纯过渡章""纯铺垫章""纯日常章"
- 章内走势为 `起点 → 章中至少一次回落/受挫 → 章末新高`
- **禁止连续两章强度下降**。回落只能持续一章，第二章必须反弹超过前高
- 每 3-5 章（一卷）出现一次强度 9-10 的卷高潮
- 最后一章**不回落**，收在高位 + 留下一系列长线钩子（网文不做余韵，做续订）

**文学模式——单峰上扬型：**

- 倒数第二或第三章为全篇最高潮（强度10），第一章从较低强度（4-5）起步，最后一章快速回落做余韵
- 类型参考曲线：
  - **悬疑/惊悚**：4→6→6→7→8→9→10→3
  - **言情**：5→6→7→6→8→7→9→4
  - **科幻/奇幻**：5→6→7→8→7→9→10→4
  - **现实主义/青春**：4→5→6→7→8→9→10→3

### 4.2 写作重点的分配（修正版）

> 旧版把写作重点在"环境描写 / 对话优化 / 心理活动"三者间轮换，导致轮到"环境描写"的章节**必然拖沓**——整章没有对手、没有台词。已废弃。

**商业网文模式的写作重点池（六选一，相邻两章不同）：**

| 重点         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| 【冲突对抗】 | 正面交锋，短句快切，动作密集                                 |
| 【打脸爽点】 | 四要素齐全，重点打磨"当面反馈"一环                           |
| 【对话交锋】 | 靠台词推进，潜台词与攻击性                                   |
| 【信息揭露】 | 抛设定/揭身份/暴露阴谋，用对话或事件带出，不用旁白讲解       |
| 【关系推进】 | 盟友/对手/情感线的关系变化，必须由事件驱动                   |
| 【危机压制】 | 主角受挫、被压制，为下一章反弹蓄力（**全书占比不得超过 15%**） |

**注意：环境描写和心理活动不再作为"章节重点"存在**——它们降级为服务性手段，随用随写，不单独成为一章的打磨目标。

**文学模式**保留原三维轮换：【环境描写 / 对话优化 / 心理活动】。

### 4.3 章末钩子类型（强制轮换）

★ **相邻两章不得使用同一种收尾方式。** 收尾库：

| 类型       | 说明                                            |
| ---------- | ----------------------------------------------- |
| 对手台词   | 反派/强者撂下一句话                             |
| 悬念提问   | 一个未解的"谁/为什么/接下来"                    |
| 突发打断   | 电话、来人、警报、伤势发作                      |
| 主角宣言   | 短句，带情绪，明确表态                          |
| 信息炸弹   | 一条颠覆认知的信息落地                          |
| 危机降临   | 更强的敌人/更大的麻烦出现                       |
| 金手指提示 | 系统面板/异象提示 ★**全书使用占比不得超过 20%** |

> 上一版正文出现"连续 5 章全部以系统面板弹字收尾"，读者第三章就能预判结尾长什么样，钩子完全失效。这是硬性禁止项。

**模板：**

```markdown
# 《[标题]》—— 章节情绪节拍表

总字数：约[N]字 | 共[N]章，每章约[N]字
模式：[商业网文 / 文学]  类型：[小说类型]
情绪强度曲线：[描述整体走势]

---

## 第一章：[章节标题]（约[N]字）
- **情绪类型**：[如：憋屈→翻盘 / 危机→反制 / 轻蔑→打脸]
- **强度**：[起始值] → [章中回落值] → [章末值]
- **核心事件**：[本章发生的最关键一件事，一句话说清]
- **本章爽点**：[类型] — [一句话]（每 2000 字 1 个，列全）
- **转折点位置**：[章末15%内]，具体说明转折点内容
- **本轮写作重点**：【冲突对抗 / 打脸爽点 / 对话交锋 / 信息揭露 / 关系推进 / 危机压制】
- **★章末钩子类型**：[从 4.3 库中选，标注与上一章不同]
- **写作提示**：[本章特有的注意事项]

---

## 第二章：[章节标题]（约[N]字）
[同上结构]

---

[后续章节同上，共N章]

---

## 整体提醒

- 检查是否存在连续两章强度下降 → 有则调整
- 检查章末钩子类型是否有相邻重复 → 有则更换
- 检查金手指提示类收尾是否超过全书 20% → 超则替换
- 检查是否存在无爽点的章节 → 有则补
```

保存到 `./output/创作材料/[标题]-情绪节拍表.md`。

**第一级：卷（Arc）级——宏观情绪弧线**

## 阶段五：分章节创作

此阶段按章节顺序生成。**中短篇模式每章确认后动笔，长篇模式按卷批量确认、卷内连续输出。**

### 5.1 中短篇模式（≤12章）：逐章确认

每章创作前，先向用户展示本章的创作参数：

**步骤一：每卷开始前，展开该卷的章级节拍表**

该卷全部章节完成后，汇总：

- ★★**本卷代入感指标汇总表**（跑 5.3-K 脚本，逐章列出感知句数 / 每500字密度 / 身体感官 / 无名情绪反馈，不达标章节当场返工）——★这项排在最前
- ★**本卷反 AI 味指标汇总表**（跑 5.3-K 脚本，逐章列出破折号/三字/句式模具计数，超标章节当场返工）
- ★**本卷爽点清单**：每章爽点数量、类型是否轮换、四要素是否齐全
- ★**本卷章末钩子类型序列**：检查相邻重复、金手指提示类占比

- 本卷对手层级是否高于上卷、冲突类型是否更换
- 角色行为一致性，标志性动作是否机械复用
- 卷末大爆爽点与卷末钩子是否到位

用户确认或修改后，展开下一卷的章级节拍表，回到步骤一。

### 5.3 通用写作规则（中短篇和长篇通用，每章强制执行）

以下规则在每一章创作中必须严格遵守，不可妥协：

**标点符号规则（最高优先级）：**

- 双引号**必须**使用中文格式 `""`，**严禁**使用英文格式 `""`
- 逗号**必须**使用中文格式 `，`，**严禁**使用英文格式 `,`
- 句号**必须**使用中文格式 `。`，**严禁**使用英文格式 `.`
- 问号**必须**使用中文格式 `？`，**严禁**使用英文格式 `?`
- 冒号**必须**使用中文格式 `：`，**严禁**使用英文格式 `:`
- 感叹号**必须**使用中文格式 `！`，**严禁**使用英文格式 `!`
- 对话引用时，引号内外的标点均遵循中文排版规范

**字数规则（软约束，优先级低于剧情质量）：**

- ★**统计口径：含标点**。平台按含标点字符计费/计数，纯汉字口径会让每章实际短掉约 18%
- 目标字数允许区间 `目标 ±200` 字
- ★**必须一稿写到目标区间**。动笔前按目标字数反推需要几个场景拍子（约每 250-300 字一拍），照拍子写
- ★**严禁"先写短稿再补段"**——分次追加会让情节密度分布不均、结构变松散。写完只做校验和收紧，不做扩写
- ★**严禁为凑字数增加环境描写、心理活动、回忆插叙、设定解释**——这是"节奏拖沓"最主要的机制性来源
- 万不得已需要补时，优先级：① 对话交锋 ② 冲突动作 ③ 对手/围观者反应 ④ 新信息落地。**四项都补不动，说明本章剧情量不够，应从下一章借情节，而不是注水**
- 超出时按此优先级删减：① 环境描写 ② 心理活动 ③ 重复的情绪陈述 ④ 解释性旁白。**不得删冲突和对话**
- 统计方法（含标点，去掉标题行与空白）：
  `python3 -c "import re,sys;t=re.sub(r'^#.*$','',open(sys.argv[1],encoding='utf-8').read(),flags=re.M);print(len(re.sub(r'\s','',t)))" 文件`

**★正文排版规则（投稿平台不解析 markdown）：**

- 章节正文里除章节标题外，**禁止出现任何 markdown 语法**：引用块 `>`、加粗 `**`、列表 `-`、代码反引号、表格
- 系统面板/金手指提示一律用**普通段落**写，不要套引用块
- 验证：`grep -n '^\s*[>*|+-] \|`\|\*\*' 章节文件`（应无输出）
- 创作材料文档（角色DNA、大纲、节拍表）不受此限，照常用表格和加粗

### ★★ 代入感强制规则（优先级高于反 AI 味，商业网文模式必执行）

> **本节是为解决"代入感不足"退稿而设。**
> 七猫官方编辑对代入感的定义是：**代入感的本质是情感共鸣，文中的情绪能被读者感知到，读者就有代入感**。并明确点名两条致命项——**「核心剧情不能只有事件而没有情绪」** 和 **「叙事不清晰（信息过载）是代入感的天敌」**。
>
> ★**本节与后面的反 AI 味规则冲突时，以本节为准。**
> 反 AI 味规则（删心理活动、删描写、事事用动作翻译情绪、句句推进剧情）如果执行到极致，会把稿子写成一台**外视角摄像机**——技术上挑不出毛病，读者却全程在"围观"主角而不是"成为"主角。这正是"节奏很快但没代入感"的成因。**先保证代入感，再在代入感的基础上去 AI 味。**

---

**L1. 视角贴身（★第一位，改这一条能解决一半问题）**

全章锁死在主角一人的感知里。主角看不见、听不到、想不到的，一律不写。

- ✗ 客观机位（作者在场外报道）：

  ```
  赵万山把这话说了两回，第二回又慢又狠，马棚底下那几个人一个字也躲不掉。
  ```

- ✓ 主角感知（读者在秦川身体里）：

  ```
  那句话赵万山说了两回。第二回说得又慢又狠，一个字一个字往秦川耳朵里砸。
  秦川后脖颈一阵发凉。这人是真敢砍。
  ```

- 硬指标：★**每 500 字至少 2 处主角感知句，全章 ≥12 处**
- 感知句的判定：出现主角的**听见 / 闻到 / 看清 / 觉得 / 心里 / 心口 / 胃里 / 嗓子眼 / 后背 / 手心 / 眼前 / 才明白 / 忽然想起 / 盘算 / 算了算 / 怕的是**这类词
- ★**旁人的心理一律不许直接写**。要写反派在想什么，只能通过主角看见的动作 + 主角的猜测来写

**L2. 每个剧情节点必须挂情绪（七猫编辑点名的头号问题）**

- ★每一次事件推进之后，**必须跟一句主角的内心反应**，哪怕只有半句。事件是骨头，情绪是肉，只有骨头读者啃不动
- ★以下四个位置**必须**有主角内心反应，不许直接跳到下一个动作：
  1. 金手指 / 系统首次出现
  2. 第一次打脸成功的那一瞬
  3. 拿到关键资源（粮、钱、人、权）的那一瞬
  4. 被羞辱、被压制、被背叛的那一瞬
- 检查方法：把全章的动作和对白全部划掉，剩下的字如果不足全章 15%，说明写成了纯事件流，返工

**L3. 金手指首现的"三拍"（缺一拍读者就没爽到）**

第一次开金手指，必须写足三拍，不许压缩成一拍：

| 拍 | 内容 | 常见漏项 |
| --- | --- | --- |
| 一、懵 | 这什么东西？我是不是被打糊涂了？主角的困惑要写出来 | ★最常漏 |
| 二、试 | 不信 → 试一次失败 → 摸到规则 → 再试成功 | 一般都有 |
| 三、爽 | 成功那一瞬的身体反应 + 一句内心宣言 | ★最常漏，也最要命 |

- ✗ 只有第二拍，主角像个没有情绪的操作员：

  ```
  他把手指挪过去，指腹蹭到饼上的湿泥，又在心里念了一次。饼没了，泥地上留个浅窝。
  得碰着才行。
  ```

- ✓ 补上第一拍和第三拍：

  ```
  秦川脑子里"嗡"的一声。他挨了四天打，还当自己是终于被打出毛病了。
  ……
  饼没了，泥地上留个浅窝。
  原来得碰着才行。秦川死死盯住那个浅窝，心口像被人捶了一拳，血一下全涌上头。
  这四天他跪在这院子里等死。眼下他手里有东西了。
  ```

**L4. 开篇专名与数字限流（"叙事不清晰是代入感的天敌"）**

读者在手机上读第一屏，脑子里要先建立"我是谁、我在哪、我怕什么"。这时候塞人名地名和算术题，读者建立不起来就划走了。

- ★**开篇 500 字内：出场人名 ≤3 个，地名 ≤1 个**
- ★**第 1 章全章：人名 ≤6 个，地名 ≤3 个**
- ★**开篇 1000 字内不得出现任何要读者做算术才能理解的数据**
- ★**计量单位换算（石 / 斗 / 升 / 合、载重、里程）严禁在第 1 章解释**，放到第 3 章之后随剧情自然带出。第 1 章只用"一袋""一车""半天路"这类不用换算的量
- 配角**一次只放一个**，每个配角出场时给他一句带个性的台词或一个动作，不要五六个人挤在同一段里各说一句

**L5. 身体感与匮乏感（灾荒 / 末世 / 年代 / 生存题材专项）**

代入感最短的路径，是让读者的身体跟着难受。

- ★每章至少 **3 处身体感官**：饿、渴、冷、疼、累、腥、馊、酸、发软、发涩
- ★**题材的核心痛苦必须让读者身体感受到**。灾荒文写饿，不能只写一个"饿"字：

  - ✗ `他已经三天没吃东西了，很饿。`
  - ✓ `粥味飘过来的时候秦川腿一软，口水泛上来是酸的，胃里那块空的地方跟着抽了一下。`
- ★第 1 章至少 1 处，且必须落在开篇 800 字内

**L6. 情绪代理人（读者的嘴）**

每个大爽点现场，必须有一个**有名有姓、情绪外放**的角色替读者把话喊出来。5.3 里"当面反馈"那一条最容易被机械满足成"有人小声嘀咕"，那是没用的。

- ✗ `马棚底下有人小声嘀咕："他袋子方才还鼓着呢，我瞧得真真的。"`
- ✓ `李狗子"嗷"地叫出来，手指头戳着赵七的腰："袋子！他袋子刚才还鼓着的！我亲眼瞧见的！"`
- 固定给 1-2 个配角挂上"情绪外放"属性（在角色 DNA 档案里标注），专门负责在爽点现场炸开
- ★禁止用"有人""众人""马棚底下"这类无名主语承担情绪反馈

**L7. 爽点必须免脑（读者不做数学题）**

- ★爽点的成立**不得依赖读者做算术、记数据，或跟上超过两步的推理链**
- 数据类爽点，必须由角色**当场把结论和情绪一起喊出来**，不能只摆前提让读者自己算：

  - ✗ `"文书上写的是十二辆车。可青石驿能拉重的大车只有八辆。一车装二十五石，八辆是二百石。剩下那一百石得再添四辆。那四辆车是谁家的？"`
  - ✓ `"驿丞，车数对不上。"苏晚棠声音发抖，还是把话说完了，"驿站拉重的大车拢共八辆，文书上却写着十二辆。多出来那四辆，压根不是驿站的。"`
- 推理型主角同理：可以推理，但**结论必须由主角自己一句话说破**，不留给读者拼

**L8. 主角起点必须"和读者一样"**

代入感的机制是：我先和他一样 → 他翻身 → 所以我也翻身。主角开局就满级冷静，读者贴不上去。

- ★**第 1 章前 1/3，主角必须先展示一个普通人的弱**：怕、疼、屈辱、无力、想活、恨得牙痒
- ★**冷静、掌控感、算无遗策，是金手指到手之后才允许出现的状态**，不许从第一句到最后一句都是同一个温度
- 全书同理：每卷主角至少露一次"人"的一面（撑不住、后怕、心软、算错）

**L9. 允许"无用的人味句"（★反直觉，但很关键）**

"每句话都要推进剧情"执行到底，文字会变成电报。读者对角色的感情，恰恰建立在那些不推进剧情的句子上。

- ★每章允许并**建议**保留 **3-5 句纯人味句**：抱怨、玩笑、走神、想起以前吃过的东西、惦记家里人
- 这类句子**不计入"废话"，节奏压缩润色时不得删除**
- 示范（本类题材效果最好的一种写法）：

  ```
  周老栓喝到一半停下，把剩的倒回自己那只豁口粗瓷罐，拿布塞紧了。
  "老栓叔，你不饿？"
  "我孙子在后院睡着。"老头低下头，不再往下说。
  ```

  这三句一点剧情都没推，却是全章读者最记得住的地方。

**L10. 侧面描写补情绪（七猫编辑推荐手法）**

情绪显得干巴时，用**物或景**从侧面托：等不到人时冷掉的粥、下属小心翼翼的神色、那天的雨。

- 每章可用 1-2 处，**必须挂在情绪节点上**，不得变成氛围铺陈
- 与 5.3-H"环境描写全章不超过 200 字"的额度共用

### ★ 反 AI 味强制规则（每章写完必须逐条验证，★冲突时让位于上面的代入感规则）

以下是平台编辑判定"AI 痕迹重""伪人感"的具体特征。**每一条都是硬性配额，写完用 bash 验证，超标必须重写。**

> ★**执行边界**：这些配额是用来防"模具感"的，不是用来删情绪的。当某条规则和 L1-L10 打架时（典型：为了少写心理活动而砍掉主角的内心反应），**一律以代入感规则为准**。宁可多一句主角内心，也不要一章冷冰冰。

**A. 破折号配额**

- 每章 `——` **不超过 5 个**
- ★**严禁**把破折号当作后置解释/反转补语的固定模具。以下写法全部禁止：
  - ✗ `不是从外面碎的——是从里面`
  - ✗ `他要的不是暴富——是稳定日收`
  - ✗ `真有权。手里没拿茶杯也没拿手机——不需要用东西占据不安的手`
- 替代方案：拆成两个独立短句、用句号断开、或直接把解释删掉让读者自己看出来
- 验证：`grep -o "——" 文件 | wc -l`

**B. 句式黑名单（每章每种最多 1 次，且相邻章不得重复使用同一种）**

- `不是A，是B` / `不是A——是B` / `不是A，而是B`
- `不是…不是…只是/而是…`（三连否定，最重的 AI 特征）
- `连…都/也…`
- `A，很B，很C`（三连形容词）
- `他不知道的是…` / `多年以后他才明白…`（上帝视角剧透，除非刻意为之）
- `像一个…` / `像一台…` / `像一块…`——**全章比喻不超过 3 个**
- 验证：`grep -oE "不是[^。！？]{1,20}[，]?是" 文件 | wc -l` 应 ≤1

**C. 数字与量词去模板化（"万事皆三"专治）**

- ★每章"三"字总出现次数（含"三年""第三""三个""三十"等**全部形态**）**不超过 8 次**
- ★**同一个时间量词全章不得出现两次**——"三秒"用过就不能再用；"两遍""五分钟"同理
- ★**停顿时长优先不写数字**。用动作或感官替代：
  - ✗ `他盯着那行字看了三秒`
  - ✓ `他盯着那行字，直到眼睛发涩`
  - ✗ `沉默了十秒`
  - ✓ `没人接话。空调外机在窗外嗡了一阵`
- 需要写数字时，**刻意避开 3/5/10 这三个默认值**，用 4、7、11、23 这类非整数感的值
- 战力/属性/金额等设定数字，**每章不超过 6 个**，其余用相对表述（"翻了一倍""比他高两个档""半年的工资"）
- 验证：`grep -o "三" 文件 | wc -l` 应 ≤8

**D. 句长与段落节奏（★易被写反，两个方向都是 AI 味）**

段落太长会拖沓，但**一路碎短句同样是重度 AI 特征**——编辑评价是"像分行诗""模板感"。两边都要卡：

- 句子以 **15-30 字**为主，长短自然交替；**平均段长控制在 25-35 字**

- 每段 **1-3 句**，不超过 60 字（手机阅读）

- ★每章需要 **≥8 个单句成段**（≤15 字）制造爆点，但**严禁连成串**——连续单句成段不得超过 **4 段**，且只允许出现在对白往返处，不允许出现在叙述段

- ✗ 反面例子（叙述性碎句连排，必改）：

  ```
  赵万山笑了。
  笑得很慢。
  像刀。
  ```

- ✓ 改法：`赵万山冷笑一声，慢慢蹲到秦川面前，那张肥脸上没有半点同情。`

- ★**禁止连续 3 段都超过 60 字**

- ★**开篇前 3 段每段不超过 45 字**

- ★**顿号三连罗列每章不超过 1 处**——`山、河、道路、桥、车辙` `路径、时效、损耗、风险` 这类名词排比是 AI 高发句式，同章出现两次以上必改

- ★**禁止"大家都……只有他……"式工整对照句**拆成两段并列。这是作者替读者做总结。

  - ✗ `院子里的人都穿草鞋。只有驿丞的靴是新的。`
  - ✓ `院里的人都穿着破草鞋，鞋底磨穿了便拿麻绳捆着，唯独赵万山脚上那双皂靴簇新。`

- 每章至少 3 处使用**不同的**强调手段（重复、反问、短句爆破、动作打断、对话被截断、独立成段的单词），不得全部依赖破折号

**E. 情绪表达去克制化（商业网文模式）**

- ★**禁止用"没说话""沉默了一会儿""脸上没有表情"作为主要回应方式**——每章此类"沉默回应"不超过 3 次
- 主角有情绪时要让读者**明确接收到**：可以写他说了什么、做了什么、身体有什么反应，但不能只写"他什么都没说"
- ★**允许说透，允许点题，允许主角放狠话**。留白、克制、余韵是纯文学审美，在免费阅读平台等于爽点缺失

**F. 章末模板防重复**

- 严格执行阶段四 4.3 的钩子类型轮换，相邻两章不得同类型
- ★"金手指/系统面板提示"类收尾全书占比不超过 20%

**G. 角色动作防机械复用**

- 严格执行阶段二的标志性动作纪律：同一动作同章最多 1 次、相邻章最多 1 次、每次描述必须换措辞

**H. 文风基调（商业网文模式，★决定读感的根本项）**

目标文风：**通俗流畅、情绪直给、对白有火气、叙事推进快，同时保留少量真实细节和生活质感**。
配比参考：**七成通俗爽文 + 两成场景生活质感 + 一成人物幽默与个性**。

- ★**不要写成冷硬文学风**。这是最容易走偏的方向：句子越写越短、情绪越写越克制、主角越写越沉默——读起来"高级"，但在免费阅读平台等于没有爽感
- ★**更不要写成"外视角摄像机"**。表现是：全章只有动作和对白，一句主角的内心都没有，读者从头到尾在"围观"主角。技术上挑不出毛病，编辑的评语就是"代入感不足"。判定方法见 L1，配额是每 500 字 ≥2 处主角感知句
- ★**允许直接写情绪**。"秦川心里那股火直往上顶"这种直给写法在网文里是正确的，不必事事都用动作翻译。最佳方式是**情绪与行动结合**，不是纯展示不说明
- ★**严禁主角"装逼不解释"**。以下写法一律禁止：
  - ✗ `"你自己想。"` / `"你会知道的。"` / `"到时候你就明白了。"`
  - ✓ 给出真实依据，依据本身就是打脸：`"我爹押了一辈子粮，我从小跟他认路。云州哪条道断了，哪条只有偷粮的人才走，我闭着眼都数得出来。你不信就派人去挖。"`
- ★**主角的威胁必须带现实后果**，不能只是狠话：
  - ✗ `"你会后悔的。"`
  - ✓ `"盐井里的粮要是烧了，明早押粮官第一个砍的不是我，是你。"`
- 对白必须分身份：驿卒村民兵卒说话短、直、带俗语，不讲现代术语；官员粮商表面讲规矩、实际推责任、爱用身份律法文书压人，不会每次都直接承认恶意
- ★**心理活动分两种，要分开处理，旧版把它们混为一谈是"代入感不足"的直接原因**：
  - **感知与反应**（他听见什么、身体什么感觉、心里立刻冒出的那半句）——★**这是代入感的燃料，必须写，且有下限要求，见 L1/L2**。不要删
  - **解释与复述**（重复正文已给出的信息、替读者总结、把刚发生的事再想一遍）——删。已经写了反派脸色变化，就不要再写"秦川知道自己猜对了"
- 判断危险、制定计划、表达明确欲望这三类**必须保留**；在此之外，主角对每个事件的即时情绪反应**同样必须保留**
- 细节只留**能参与剧情**的：新靴与破草鞋体现身份差、钥匙上的盐霜是线索、粮袋里的沙说明掺假、草鞋上的碱土暴露路线。删掉纯为文艺的云风月色

**I. 逻辑与常识核算（★很多稿子不是文风像 AI，是数字像模型随手生成）**

- ★开书时必须在大纲里建立**计量标准表**并全书遵守：重量单位换算、车辆载重、行进速度、单人负重、粮价基准
- 每章写完核算：**距离 ÷ 速度 = 时间**是否对得上？**数量 × 单重 = 总重**车拉得动吗？容器装得下吗？
- 常见翻车：腰间布袋写"四斗二升"（几百斤，挂不住，应为"四升二合"）；一车装四十石（超两吨，应减载量或增车数或明确是四马重车）
- 若要论证"来不及派人去查"，必须给足条件：天色已晚、对方留了望风、见官马就提前纵火、单人到了也确认不了地下情况
- 任何新能力出现后立刻自检：**它会不会让此前和此后的困难失去意义**

**J. 人物不得为主角服务（★"编排感"的根源）**

- ★**反派不许降智**。反派发现主角接近真相后，最合理的行为是灭口。若让主角活着离开，必须给出**现实理由**（上级即将抵达、主角是文书经手人、想放长线钓出同伙、埋伏已经布好认为主角必死），并给他**第二套方案**
- ★**配角不许轮流为主角递话**。典型编排：甲证明道路塌了、乙证明地点存在、丙介绍主角父亲、女主补充数据、小反派负责展示金手指——每人完成一个功能，痕迹极重
  - 修正：让配角有自己的利益；**有人说真话，也要有人撒谎**；帮主角是因为能吃上饭或能活命；拒绝主角是因为怕被报复
  - 同一条信息尽量靠**现场证据**完成，不让多人排队补充。例：配角故意否认道路塌方，主角从他草鞋上的碱土拆穿——一个人完成"说谎"和"被打脸"两件事，比两个人各递一句强
- ★**主角不许永远正确**。第一次用金手指要有**试探**（先试一次没成功，摸到规则才成功）；判断正确必须有证据；计划里必须留风险；主角可以紧张，但不能慌乱
- ★**金手指不许一次打印全部答案**。分阶段给：第一次只给`目标 / 方位 / 状态 / 剩余时限`，主角决定追查后才展开路线推演。金手指负责提供优势，**主角负责做选择**
- ★**爽点必须有观众**。胜利要被曾经瞧不起他的人、被他保护的人、等着吃饭的灾民、不信他的官兵、被迫低头的反派亲眼看见。没有观众的胜利能推进剧情，但情绪收益极低

**文风规则：**

- ★基调见 5.3-H：**通俗流畅、情绪直给、对白有火气、叙事推进快**，七成通俗爽文 + 两成生活质感 + 一成幽默。**不要冷硬文学风**

### 6.0 代入感润色（★全稿必跑，最高优先级，排在去 AI 味之前）

> 顺序理由：去 AI 味是**做减法**（删模具、删冗余），代入感是**做加法**（补感知、补情绪、补身体感）。先加后减，最后由 6.2 收紧；反过来做，刚补进去的情绪会被 6.1 当成"心理活动"删掉。

**先跑一遍全稿代入感体检：**

```bash
for f in ./output/章节正文/*.md; do
  python3 - "$f" <<'EOF'
import re, sys, os
t = open(sys.argv[1], encoding='utf-8').read()
w = len(re.sub(r'\s','',re.sub(r'^#.*$','',t,flags=re.M)))
P = len(re.findall(r'(听见|听得|闻到|闻见|看清|觉着|觉得|心里|心口|胸口|胃里|嗓子眼|后脖|后背|手心|眼前|鼻子里|才明白|忽然想起|想起|盘算|算了算|怕的是)', t))
B = len(re.findall(r'(饿|渴|冷|疼|酸|累|腥|馊|发软|发涩|发凉|发紧|打颤|哆嗦|咽了口|口水|喘)', t))
A = len(re.findall(r'(有人小声|有人嘀咕|众人|旁边有人|不知谁|有人低声)', t))
print(f"{os.path.basename(sys.argv[1])[:-3]:<22} 字数{w:<6} 感知{P:<4}(≥12) 每500字{P/max(w/500,1):.1f}(≥2) 身体感{B:<3}(≥3) 无名反馈{A}(=0)")
EOF
done
```

**润色指令：**

```markdown
请只针对【代入感】这一个维度优化，不改动剧情走向、人物关系和章末钩子：

1. **视角贴回主角身上**：全章逐句检查，凡是"作者在场外报道"的句子，改写成主角的所见所闻所感。
   - 找出所有以旁人或环境为主语、描述客观事实的叙述句
   - 改成：主角看见/听见了什么 + 他心里立刻冒出的那半句反应
   - ★删掉一切对旁人心理的直接描写，改成主角看见的动作 + 主角的猜测

2. **给每个剧情节点挂上情绪**：逐个事件检查，事件推进之后有没有主角的内心反应。
   ★以下四处必须补足：金手指首现、第一次打脸成功、拿到关键资源、被羞辱压制

3. **金手指首现补三拍**：检查第一次开金手指的段落，"懵"和"爽"这两拍在不在。
   缺"懵"就补主角的困惑，缺"爽"就补成功那一瞬的身体反应和一句内心宣言

4. **补身体感官**：每章补足 3 处以上（饿、渴、冷、疼、累、酸、发软）。
   ★灾荒/生存题材的核心痛苦必须让读者身体感受到，不能只写一个"饿"字

5. **无名情绪反馈实名化**：把"有人小声嘀咕""众人哗然""马棚底下有人说"全部改成
   有名有姓的角色 + 外放的情绪 + 具体台词

6. **爽点去数学化**：找出所有需要读者做算术或跟推理链才能爽到的地方，
   改成由角色当场把结论和情绪一起喊出来

7. **开篇减负（仅第 1-3 章）**：开篇 500 字内人名压到 3 个以内、地名 1 个以内；
   开篇 1000 字内删掉所有需要算术的数据；计量单位换算全部挪出第 1 章

8. **主角降温（仅第 1 章前 1/3）**：金手指到手之前，主角必须先有普通人的怕、疼、屈辱、无力。
   删掉这一段里所有"算无遗策"的表现

9. **补人味句**：每章补 3-5 句不推进剧情的人味句（抱怨、玩笑、走神、惦记家人）。
   ★这些句子后续压缩润色时不得删除，请在返稿中单独标出来

请返回修改后的全文，并附一张表：本章补了几处感知、几处身体感、几处人味句，
分别在哪个位置，改前改后各举 3 例。
```

### 6.1 去 AI 味润色（全稿必跑，最高优先级）

**先对全稿跑一遍统计，按超标严重程度排序处理：**

```bash
for f in ./output/章节正文/*.md; do
  echo "=== $(basename $f)"
  echo "  破折号 $(grep -o '——' $f|wc -l)/5  三 $(grep -o '三' $f|wc -l)/8  不是A是B $(grep -oE '不是[^。！？]{1,20}[，]?是' $f|wc -l)/1  沉默 $(grep -oE '没说话|沉默了|没有表情' $f|wc -l)/3"
done
```

```markdown
请只针对【去除 AI 写作痕迹】这一个维度优化，不改动剧情、人物和章节结构：

1. **破折号**：本章 `——` 削减到 5 个以内。★重点铲除"后置解释/反转补语"模具——凡是 `X——其实是Y`、`不是A——是B` 一律拆成独立短句、改成句号断开，或直接删掉解释部分让读者自己看出来
2. **句式模具**：`不是A是B`、`不是…不是…只是…`、`连…都…`、`A，很B，很C` 每种全章最多保留 1 次，其余改写成陈述句、疑问句、对话或动作
3. **"三"字**：全章削减到 8 次以内。优先改掉时间/次数量词里的"三"（三秒、三遍、三次、三个月），改用 4/7/11/23 这类值，或直接删掉数字改用动作描述
4. **重复量词**：全章扫描同一时间量词是否出现两次以上（如两处"三秒"、两处"两遍"），有则改掉其中一处
5. **停顿写法**：`看了X秒`、`沉默了X秒`、`顿了大概X秒` 这类写法全章最多保留 1 处，其余改用动作或环境音替代
6. **段落节奏**：拆掉超过 60 字的段落；确保没有连续 3 段都超过 60 字；开篇前 3 段每段压到 45 字以内；补足单句成段（≤15字）到 8 处以上。★**反向也要查**：连续单句成段超过 4 段的地方，把叙述性碎句合并回正常句子——一路分行是和长段拖沓同等严重的 AI 特征，平均段长应落在 25-35 字
6b. **顿号排比**：全章名词顿号三连（`A、B、C，全是…`）压到 1 处以内，其余改写成动词句或直接删项
6c. **工整对照句**：`大家都……只有他……` 这种拆成两句的对照结构，合并成一句自然叙述（`院里的人都穿破草鞋，鞋底磨穿了拿麻绳捆着，唯独他脚上那双簇新`）
6d. **档案式介绍**：`姓名，X岁，身份是……` 这类旁白报设定，改成从动作或对话里带出
6e. **重复强调模具**：`X。太X了。`、`没有A，没有B。` 这类对仗式强调全章最多 1 处
6f. **装逼不解释**：`你自己想`、`你会知道的`、`到时候你就明白` 全部改成给出真实依据的具体台词
7. **比喻**：全章比喻不超过 3 个，删掉最平庸的那几个（尤其是"像一台/像一个"起头的）
8. **强调手段多样性**：检查本章的情绪强调是否全部靠破折号完成，改成重复、反问、短句爆破、动作打断、对话被截断等至少 3 种不同手段

请返回修改后的全文，并附一张"改动前/改动后"对照表（列出被改掉的模具句，各举 3-5 例）。
```

### 6.2 节奏压缩润色（全稿必跑，商业网文模式）

```markdown
请只针对【节奏】这一个维度优化，不改动核心剧情走向：

1. **删铺陈**：找出所有"为了氛围而写"的环境描写和"反复陈述同一情绪"的心理活动，直接删除。商业网文模式下单章环境描写总量不超过 200 字
   - ★★**保护清单，以下三类一律不许删**：① 主角的感知句和即时情绪反应（代入感燃料，见 L1/L2）② 身体感官句（见 L5）③ 6.0 补进去并标注过的人味句（见 L9）
   - ★"删心理活动"删的是**复述型**心理（把刚发生的事再想一遍、替读者总结），**不是**主角的实时感受。删错方向就会重现"代入感不足"的退稿
2. **前置冲突**：检查每章开头 300 字——如果是环境/回忆/心理/设定开篇，改写成从正在发生的冲突场景切入，把交代性内容拆散到冲突过程中顺带带出
3. **补当面反馈**：找出所有"全场安静""没有人说话""无人应答"式的爽点收尾，★全部改写成具体的当面反馈——对手的失态动作 + 围观者的议论台词
4. **补主角回应**：找出所有主角沉默、冷处理、转身就走的场景，改成主角有明确回应（一句短台词或一个明确姿态）
5. **删无效章节**：找出零冲突、零对手、零台词的章节（如"主角独自修炼/独自计算/独自观察"整章），要么给它加一个当场的对手和交锋，要么把它压缩后并入相邻章
6. **章末钩子**：检查相邻章是否用了同一种收尾方式，重复的按 4.3 的钩子库换成别的类型；金手指提示类收尾全稿占比压到 20% 以内
7. **数字密度**：战力/属性/金额类设定数字每章压到 6 个以内，其余改成相对表述

请逐章返回修改方案（删了什么、改了什么、为什么），确认后再执行。
```

## 长篇跨会话续写机制（长篇模式专用）

长篇创作（≥13章）必然跨越多个会话。以下机制确保每次续写无缝衔接。

### 进度汇总文件（核心）

在 `output/创作材料/` 下维护 **《[标题]-创作进度汇总.md》**，作为续写的唯一入口。必须包含七个板块：

| 板块                        | 内容                                                         | 更新频率   |
| --------------------------- | ------------------------------------------------------------ | ---------- |
| **一、项目概览**            | 书名/平台赛道/创作模式（商业网文·文学）/类型/篇幅/叙事视角/字数标点规则/进度百分比 | 每卷更新   |
| **二、已完成卷一览**        | 每卷：核心事件、卷弧线、卷末大爆、卷末钩子、各章标题+字数+写作重点+章末钩子类型 | 每卷追加   |
| **三、角色与设定状态**      | 各主要角色当前状态（实力/处境/关系）、新登场角色、已用过的标志性动作出场记录 | 里程碑更新 |
| **四、金手指/世界观机制表** | 所有已解锁能力或设定的名称 + 当前数值状态 + 已声明的限制与代价 | 里程碑更新 |
| **五、爽点与冲突台账**      | ★已用爽点类型序列（防重复）、已用对手及层级、已用冲突类型、下一卷计划 | 每卷更新   |
| **六、关键伏笔与待回收**    | 伏笔描述 + 预设回收位置 + 当前状态                           | 每卷更新   |
| **七、续写操作指南**        | 下一步卷名/章范围/卷核心/启动步骤/文件目录                   | 每卷更新   |

> 板块五在**文学模式**下改为记录"主题意象与价值转折台账"。

**额外必须维护的一张表（商业网文模式）——代入感 + 反 AI 味累计台账：**

```markdown
| 章号 | ★感知句 | ★感知/500字 | ★身体感 | ★无名反馈 | 破折号 | 三 | 不是A是B | 沉默回应 | 单句成段 | 章末钩子类型 |
|------|--------|------------|--------|----------|-------|----|---------|---------|---------|------------|
| 第1章 | 14 | 2.8 | 4 | 0 | 4 | 6 | 1 | 2 | 9 | 主角宣言 |
```

用途：① 逐章卡指标 ② 查章末钩子是否相邻重复 ③ 统计金手指提示类收尾的全书占比 ④ ★盯住感知句是否随着卷数推进逐渐掉下来——写到后面越写越"熟练"、越写越像摄像机，是长篇最常见的滑坡。

**板块更新时机**：

- **每卷必更**：一（进度数字）、二（新增该卷记录）、五（爽点/对手/冲突类型追加）、六（新伏笔+状态变更）、七（下一步）、反AI味台账（逐章追加）
- **里程碑更新**：三（新角色登场/角色状态质变）、四（解锁新能力/设定扩展）

### 记忆文件（快速还原）

保存关键数据供会话启动时快速读取，避免每次续写都重新加载全部创作材料。记忆文件存放在**当前项目目录**下的 `.claude/memory/` 中（目录不存在则先创建）：

```
项目目录/
  .claude/
    └── memory/
        ├── MEMORY.md                  ← 索引
        ├── novel-project-status.md    # 核心数字+续写入口
        └── <标题>-创作进度汇总.md     # 进度摘要快照
```

**`novel-project-status.md` 模板**：

```markdown

metadata:
  type: project

- 功能1
- 功能2

### 续写入口
从第Y章开始。先读取 `output/创作材料/<标题>-创作进度汇总.md`。

**Why**：长篇跨会话续写，汇总文档记录所有伏笔、角色状态、系统机制。
```

**`<标题>-创作进度汇总.md`**（记忆版）是完整进度汇总的精简快照，只保留最新状态和续写入口，详细数据始终以 `output/` 下的完整版为准。

### CLAUDE.md（项目级指令）

项目根目录的 `CLAUDE.md` 记录每次会话都会自动加载的最小重启指令：

```markdown
# 《标题》创作项目

## 项目状态
X/250章完成（百分比），N卷完结。

## 核心规则
- 每章字数、标点格式
- 使用 skill 路径
- 按卷批量生成

## 续写流程
1. 读取 `output/创作材料/<标题>-创作进度汇总.md` 获取完整状态
2. 按 skill 长篇模式流程创作

## 关键文件
| 文件 | 说明 |
|------|------|
| `output/创作材料/<标题>-创作进度汇总.md` | 完整进度、伏笔、角色状态 |

```

### 跨会话续写流程

每次用户说"继续写小说"：

1. **读取入口**：`output/创作材料/<标题>-创作进度汇总.md` → 获取完整状态
2. **按需补充**：根据当前卷需求，读取角色DNA、故事大纲、卷级节拍表

**与卷末存档的关系**：手动存档是增量备份，卷末存档是完整结算。两者互补——手动存档随时可用，卷末存档在每卷完成后自动执行。

### 全稿体检：代入感 + AI 味（投稿前必跑）

投稿到七猫/番茄等平台前，对全稿跑一次体检并输出报告。
★**代入感三列（感知/身体感/无名反馈）排在最前，因为它是编辑退稿率最高的一项**：

用 python3 实现（跨平台、按字符计数，避免 awk 的字节/字符差异）：

```bash
python3 - <<'EOF'
import re, glob, os
FILES = sorted(glob.glob('./output/章节正文/*.md'))
PERC = r'(听见|听得|闻到|闻见|看清|觉着|觉得|心里|心口|胸口|胃里|嗓子眼|后脖|后背|手心|眼前|鼻子里|才明白|忽然想起|想起|盘算|算了算|怕的是)'
BODY = r'(饿|渴|冷|疼|酸|累|腥|馊|发软|发涩|发凉|发紧|打颤|哆嗦|咽了口|口水|喘)'
ANON = r'(有人小声|有人嘀咕|众人|旁边有人|不知谁|有人低声)'
print(f"{'章节':<20}{'字数':>6}{'★感知':>7}{'★密度':>7}{'★身体':>7}{'★无名':>7}{'破折号':>7}{'三':>5}{'不是A是B':>9}{'沉默':>6}{'单句段':>7}{'长段串':>7}{'开篇最长':>9}")
bad = []
for f in FILES:
    t = open(f, encoding='utf-8').read()
    paras = [p.strip() for p in t.split('\n') if p.strip() and not p.startswith('#')]
    L = [len(re.sub(r'\s', '', p)) for p in paras]
    wc = sum(L)
    m = {
        'W': wc,                                                            # ★含标点
        'C': len(re.findall(PERC, t)),                                      # ★感知句
        'V': round(len(re.findall(PERC, t)) / max(wc/500, 1), 1),           # ★每500字感知密度
        'B': len(re.findall(BODY, t)),                                      # ★身体感官
        'A': len(re.findall(ANON, t)),                                      # ★无名情绪反馈
        'D': t.count('——'),
        'S': t.count('三'),
        'N': len(re.findall(r'不是[^。！？\n]{1,20}[，]?是', t)),
        'Q': len(re.findall(r'没说话|沉默了|没有表情|没有回答', t)),
        'P': sum(1 for x in L if x <= 15),                                  # 单句成段
        'R': sum(1 for i in range(len(L)-2) if all(x > 60 for x in L[i:i+3])),  # 连续3段>60字
        'H': max(L[:3]) if L else 0,                                        # 开篇前3段最长
    }
    print(f"{os.path.basename(f)[:-3]:<20}{m['W']:>6}{m['C']:>7}{m['V']:>7}{m['B']:>7}{m['A']:>7}{m['D']:>7}{m['S']:>5}{m['N']:>9}{m['Q']:>6}{m['P']:>7}{m['R']:>7}{m['H']:>9}")
    for k, lim, ok in [('C',12,'ge'),('V',2,'ge'),('B',3,'ge'),('A',0,'le'),
                       ('D',5,'le'),('S',8,'le'),('N',1,'le'),('Q',3,'le'),('P',8,'ge'),('R',0,'le'),('H',45,'le')]:
        if (m[k] > lim) if ok == 'le' else (m[k] < lim):
            bad.append(f"{os.path.basename(f)} {k}={m[k]} (限{ok} {lim})")
print(f"\n{'合格线':<20}{'—':>6}{'≥12':>7}{'≥2':>7}{'≥3':>7}{'0':>7}{'≤5':>7}{'≤8':>5}{'≤1':>9}{'≤3':>6}{'≥8':>7}{'0':>7}{'≤45':>9}")
print(f"\n超标项 {len(bad)} 处：" + ("\n  " + "\n  ".join(bad) if bad else " 无，通过"))
print("说明：C=感知句 V=每500字感知密度 B=身体感官 A=无名情绪反馈（前四项为代入感指标，优先返工）")
EOF
```

**判定标准**（任一列超标即需返工。★代入感四项回到 6.0 润色，其余回到 6.1）：

| 列            | 合格线   | 超标含义                                 |
| ------------- | -------- | ---------------------------------------- |
| ★感知句 C     | ≥12/章   | ★**代入感头号指标**。不足说明写成了外视角摄像机，读者在旁边看而不是在主角身体里——这是"代入感不足"退稿的直接原因 |
| ★感知密度 V   | ≥2/500字 | 只在开头堆几句感知、后半章全是事件流，同样不算达标 |
| ★身体感官 B   | ≥3/章    | 灾荒/生存题材尤其致命。读者的身体没跟着难受，就代入不进去 |
| ★无名反馈 A   | 0        | "有人小声嘀咕""众人哗然"承担情绪反馈＝爽点没落地，见 L6 |
| 破折号        | ≤5       | 编辑最容易一眼识别的 AI 特征             |
| 三            | ≤8       | "万事皆三"，大模型量词默认值             |
| 不是A是B      | ≤1       | 句式模具化                               |
| 沉默          | ≤3       | 主角冷处理，爽点缺失                     |
| 单句段        | ≥8       | 不足说明段落太长，节奏拖沓               |
| ★连续单句串   | ≤4       | 超了说明写成了分行诗，和长段拖沓同等严重 |
| ★平均段长     | 25-35 字 | 低于 25 是碎短句流，高于 35 是拖沓       |
| ★顿号三连     | ≤1/章    | 名词排比是高发 AI 句式                   |
| ★字数(含标点) | 目标±200 | 纯汉字口径会短掉约 18%                   |

**另需人工确认的项（脚本一条也查不了，★不做等于白做）：**

0. ★★**代入感通读（排在最前，因为这是退稿率最高的一项）**：
   - 随机挑三章连读，读完问自己：**我刚才在主角身体里，还是在旁边看？** 答"在旁边看"就整章回炉 6.0
   - 打开第 1 章前 800 字：主角有没有先像个普通人一样怕过、疼过、屈辱过？没有就重写（见 L8）
   - 找到金手指首现那一段：**懵**和**爽**这两拍在不在？只有"试"这一拍就是漏了（见 L3）
   - 数一遍第 1 章开篇 500 字里的人名和地名：人名超 3 个、地名超 1 个就删减合并（见 L4）
   - 找出全书最大的三个爽点：现场有没有一个**有名有姓、情绪外放**的角色替读者喊出来？（见 L6）
   - 挑一个数据类爽点：读者需要动笔算吗？需要就改成角色当场说破结论（见 L7）
1. 打开第 1 章，只读前 500 字——金手指/核心悬念出现了吗？没有就重写第 1 章
2. 把全部章末最后一段抽出来排一列——有没有连续两章长得一样？有就换钩子类型
3. **通读找模具句**：`X。太X了。`、`没有A，没有B。`、`大家都……只有他……`、`姓名，X岁，身份是……`
4. **查配角编排感**：本章是不是每个配角各递一句话，正好凑齐主角需要的信息？有没有人撒谎、有没有人为自己的利益说话？
5. **查反派智商**：反派放过主角的理由写出来了吗？他有没有第二套方案？
6. **核算数字**：距离÷速度、数量×单重、容器容量，逐项验算
7. **朗读全文**：一口气读不顺就改句子；连续几段像念标语就合并；一句话读完没给新信息就删

## 使用示例

### 示例一：商业网文（投稿七猫）

用户输入：

> 我想写一个都市系统流，主角是被公司开除的底层测试员，绑定了万物兑换系统，投七猫，200章，每章2500字。

Skill 执行：

1. 确认规划 → 平台=七猫 → ★**判定为商业网文模式**；追问金手指的机制与代价 →
2. 生成角色DNA档案（含反派轻蔑台词模板 + 每个配角的反馈功能 + 标志性动作的3种变体与演化路线）→
3. 走 **3A 商业网文大纲**：黄金三章（第1章500字内系统落地、第2章当面打脸、第3章中期目标+强敌）+ 爽点节拍（每2000字1个，类型轮换）+ 冲突升级表（每卷换对手换冲突类型）→
4. 生成卷级节拍表（锯齿上行，首章强度≥7，章末钩子类型轮换）→
5. 逐章创作（★先按 5.3-L 保代入感，再按 5.3-A~J 卡反 AI 味配额，每章写完跑 5.3-K 验证脚本）→
6. ★6.0 代入感润色 → 6.1 去 AI 味润色 → 6.2 节奏压缩润色 → 分维度润色 →
7. 投稿前跑"全稿体检：代入感 + AI 味"

### 示例二：文学模式

用户输入：

> 我想写一个悬疑短篇，"一个退休法医在整理妻子遗物时发现她不是意外死亡"，8章每章2500字，小镇背景，投征文比赛。

Skill 执行：

1. 确认规划 → 征文 → ★**判定为文学模式** →
2. 生成4个角色的DNA档案 →
3. 走 **3B 麦基剧作法大纲**（激励事件、故事脊椎、进展纠葛、危机高潮结局）→
4. 生成8章情绪节拍表（单峰上扬，悬疑曲线 4→6→6→7→8→9→10→3）→
5. 逐章创作（反 AI 味规则中的 A/B/C/D/G 项仍然生效，E/F 项放宽）→
6. 6.1 去 AI 味润色 → 按每章写作重点分维度润色

> ★ 反 AI 味规则里的 **A（破折号）B（句式黑名单）C（数字量词）D（段落节奏）G（动作复用）** 两种模式都必须执行——这些是 AI 文本特征，与文学性无关。只有 **E（情绪去克制化）F（章末钩子）** 是商业网文模式专属。
>
> ★ **代入感规则（5.3-L）在文学模式下的适用范围**：**L1（视角贴身）L2（事件挂情绪）L5（身体感官）L9（人味句）L10（侧面描写）同样必须执行**——代入感是叙事基本功，与商业性无关。只有 **L3（金手指三拍）L4（专名限流）L6（情绪代理人）L7（爽点免脑）L8（主角起点降温）** 是商业网文模式专属，文学模式可放宽或跳过。
